# Re-Testing LLM-Based C-to-Rust Translations Against Their Original C: artifact

Re-testing the released translations of LLM-based C-to-Rust systems against their original C.

This is the artifact for the arXiv version of the paper (`paper/main.pdf`); its numbers differ from
the version submitted to ReCode.

Each system checks its own translations (a model checker, a fuzzer, symbolic execution or a test
suite) and reports how often they pass. This artifact re-tests what the systems released: it builds
the original C as the oracle and the system's own Rust, runs both on generated inputs, compares
every observable output, counts a divergence only where the C is free of undefined behaviour, groups
divergences into defects confirmed in the translated source, and measures, from each artifact,
whether the system's own check accepted the defective translation and whether it ran an input that
exposes the defect.

## What is in this repository

| Folder | Contents |
|---|---|
| `systems/<name>/` | per-system fetch script (pinned commit), drivers, harness and notes |
| `harness/` | shared harness code: input generation, the undefined-behavior rule, held-out checks, mutation analysis |
| `scripts/` | defect ledger, tables, figures, pipeline manifest tools, explorer and dashboard builders, labeling page builder |
| `results/` | every result file the paper's numbers come from |
| `docker/` | pinned Docker images and build scripts |
| `docs/` | survey evidence for all 34 systems, partial comparisons; `docs/reviews/second-rater/` holds the blind labeling sample and its ratings |
| `explorer/` | defect explorer (`index.html`, every candidate defect) and the blind labeling app (`rate.html`), served by `explorer/serve.py` |
| `dashboard.html` | a one-page guide to the artifact: the paper's headline numbers, per-system results and where things are |
| `paper/` | the arXiv version of the paper (`paper/main.pdf`); its figures are drawn from `results/` |

Third-party artifacts are not included. Each system's `fetch.sh` downloads it at a pinned commit
into `artifacts/`; [REPRODUCE.md](REPRODUCE.md) lists every fetch command, pin and size.

Quick checks:

```bash
bash docker/quickstart.sh                             # offline: pipeline verify, figures, explorer and dashboard from results/
python3 scripts/pipeline.py verify                    # re-runs the cheap stages; the defect-ledger stage needs artifacts/
bash scripts/provision.sh artifacts                   # fetches every system's artifact at its pinned commit (about 8 GB)
python3 scripts/plot_results.py --out out/figures     # redraws Figs. 1 and 2 from results/ (verify compares them)
python3 explorer/serve.py                             # http://127.0.0.1:8790/ (explorer), /rate.html (labeling app; code from artifacts/, answers to out/)
```

*Tested*: translations we can build and drive (unit per system: function, library or program).

for each defective translation (a re-run of the documented check is used only where nothing is

system's check did not run, measured against the inputs the artifact records (for VERT, the inputs its
released commands run; n.m.: none recorded). This is the paper's held-out measure.

## Method in brief

- **Oracle:** the original C, built with its own build files (else gcc); the Rust as released. Where
  our compiler differs from the one an artifact pins or documents (VERT, RustAssure, SACTOR, ACTOR),
  rebuilding with that compiler changes no verdict (`results/toolchain_audit.json`,
  `results/arxiv_*pinned*.json`, `results/arxiv_vert_pinned_grid2.json`). `pipeline.json` names, per stage,
  the image it ran in (images and their toolchains are pinned in `docker/`) or the wrapper script that
  selects its toolchain; `systems/<name>/notes.md`, where present, adds per-system notes on toolchains.
- **UB rule (one rule, all systems):** a divergence counts only on an input where the C passes ASan +
  UBSan under GCC and Clang, gives identical results at `-O0`/`-O1`/`-O2`, and does not depend on the
  signedness of `char` (`harness/oracle_ub_common.py`).
- **Units:** a *defect* is one mechanism in a translation's source, confirmed by reading it; case
  counts are exposure only. Not counted (the paper's rules i-v): a divergence that occurs only (i) where
  the C has undefined behavior (the UB rule above), (ii) on inputs that break a precondition the
  original states in its name, comments or documentation, (iii) in a value the C standard leaves
  unspecified, (iv) in a callback that frees memory, or (v) when a negative value is passed to a
  `scanf` `%u` or `printf` `%x`/`%u` conversion. The oracle is the C as built by GCC/Clang for LP64
  Linux with glibc.
- **Platform:** RustMap's Rosetta results and the C2SaferRust grid are x86-64 runs (Rosetta outputs
  differ by architecture; C2SaferRust's `head` takes its pipe path for regular files because the C2Rust code
  it rewrites declares aarch64's `struct stat`, and an aarch64-only `head` defect that this routing hides is
  noted, not counted, in `results/arxiv_c2saferrust_head_aarch64.json`); VERT's primary grid is arm64 (an x86-64 re-run changes no verdict).
- **Build profile:** each system's Rust is built in the profile its own pipeline uses (His2Trans in both;
  FLOURINE optimized with overflow checks, which makes two overflow defects, `lfo_am_depth` and
  `compute_phase_step`, panic). All counted crashes and the wrong outputs in integer code were re-run in the other
  profile: 86 of 88 still diverge; the other two are those FLOURINE panics
  ([`results/profile_check.json`](results/profile_check.json)).
- **Kinds:** a counted defect is a *wrong output* (a different return value, exit code or primary
  output) or a *crash*. Stderr-only differences, hangs and build failures are not counted. The
  ledger's `severity` field spells these S1 (wrong output), crash, S2 (stderr only) and S3 (build
  failure or hang).

## Reproduce

See [`REPRODUCE.md`](REPRODUCE.md). From the result files (the last line also needs `artifacts/`):

```bash
python3 -I scripts/make_tables.py --md             # the table above
python3 scripts/plot_results.py --out out/figures  # Figs. 1 and 2, plus two extra figures (needs matplotlib)
python3 scripts/plot_overlap.py --out out/figures  # Fig. 3 (needs matplotlib)
python3 -I scripts/build_defect_ledger.py          # rebuild results/defect_ledger.json and run its checks (needs artifacts/)
```

Re-running a system end to end needs its public artifact (`systems/<system>/fetch.sh`) and the
Docker images in `docker/`.
